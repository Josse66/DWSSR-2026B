# ⚙️Convención de iconos para commits:
Los tipos de commits mas comunes en un proyecto de desarrollo web, con su proposito en desarrollo.
## Conventional commits:
| Icono | Tipo | Significado / uso |
|---|---|---|
| ✨ | `feat` | Agrega una funcionalidad nueva al proyecto. Ej: nuevo endpoint, nuevo componente de UI. |
| 🐛 | `fix` | Corrige un bug o comportamiento incorrecto en el código existente. |
| 📝 | `docs` | Cambios solo en documentación: README, comentarios, wikis, guías. |
| 💄 | `style` | Formato, espacios, punto y coma, indentación. No cambia lógica ni CSS visual. |
| ♻️ | `refactor` | Reestructura código sin cambiar su comportamiento externo ni agregar features. |
| ⚡ | `perf` | Mejora el rendimiento: tiempos de carga, consultas, uso de memoria. |
| 🧪 | `test` | Agrega o corrige pruebas: unitarias, de integración, end-to-end. |
| 📦 | `build` | Cambios en el sistema de build o dependencias: webpack, npm, vite, docker. |
| ⚙️ | `ci` | Cambios en configuración de integración continua: GitHub Actions, pipelines. |
| 🧹 | `chore` | Tareas de mantenimiento que no tocan código de producción ni tests. |
| ⏪ | `revert` | Revierte un commit anterior. Suele generarse automático con git revert. |
